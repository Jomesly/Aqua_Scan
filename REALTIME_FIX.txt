PROBLEM FIXED:
═══════════════════════════════════════════════════════════════════════

The dashboard was only showing the FIRST reading and not updating
in real-time because the Arduino was initialized AFTER the sensor_worker
thread started.

THE FIX:
═══════════════════════════════════════════════════════════════════════

Moved Arduino initialization to happen BEFORE telemetry.init():

OLD ORDER (broken):
  1. telemetry.init() → starts sensor_worker
  2. sensor_worker checks Arduino (not initialized yet!)
  3. Arduino initialization (too late!)
  4. sensor_worker keeps using simulated data

NEW ORDER (fixed):
  1. Arduino initialization (connects to COM5)
  2. telemetry.init() → starts sensor_worker
  3. sensor_worker finds Arduino ready → reads real temperature
  4. Database updated every 2 seconds with Arduino data
  5. Dashboard polls every 2 seconds → shows real-time updates

═══════════════════════════════════════════════════════════════════════

HOW IT WORKS NOW:
═══════════════════════════════════════════════════════════════════════

Real-time data flow:

  Arduino (COM5)
    ↓ (every 2 seconds)
  {"status":"ok","temperature_c":19.7}
    ↓
  arduino_serial_bridge (background thread)
    ↓
  arduino_integration

  sensor_worker (background thread, started AFTER Arduino ready)
    ↓
  _record_reading(19.7, None, True, simulated=False)

  Database: tilapiers.db (sensor_readings table)
    ↓
  /api/environment endpoint
    ↓
  Dashboard polls every 2 seconds
    ↓
  Environmental Parameters shows: 19.7°C
    ↓ (updates every 2 seconds)
  Shows live temperature in real-time!
